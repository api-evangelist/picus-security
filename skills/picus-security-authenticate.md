# Authenticate to the Picus Customer API

Every Picus endpoint except the token endpoint requires a bearer access token. Access tokens live **2 hours**; the refresh token that mints them lives **6 months**.

## Prerequisites
- A refresh token, generated by a human in the Picus console: `app.picussecurity.com` > **Settings** > **Rest API Token** > **Generate Token**. The panel asks for a name, description, expiration in days, and a **scope** that filters which endpoints the token may reach. The token is displayed **once** — it cannot be retrieved again.
- Base URL: `https://api.picussecurity.com/`.

## Steps
1. **Mint an access token** — `AuthTokenParam` (`POST /v1/auth/token`). Send `Content-Type: application/json` and a body of `{"refresh_token": "<refresh token>"}`. No `Authorization` header on this call.
   Response: `{"token": "<access token>", "expire_at": <unix epoch milliseconds>}`.
2. **Call the API** — put the access token on every subsequent request as `Authorization: Bearer <token>`. Example: `GET /v1/simulations` (`simulationListParams`).
3. **Refresh before expiry** — track `expire_at` (milliseconds, not seconds) and re-run step 1 before it passes. Do not wait for a `401`.
4. **Rotate the refresh token** — `RegenerateRefreshTokenParam` (`POST /v1/auth/refresh`) issues a new refresh token and **invalidates the previous refresh and access tokens**. If the refresh token has already expired, this endpoint cannot help — a human must generate a new one from the console.

## Rules
- One credential, one header. There is no per-request signing, no API key query parameter, and no client_id/client_secret.
- The token exchange is Picus-proprietary, not RFC 6749: there is no `grant_type`, no `token_type`, no `expires_in`. Do not point a generic OAuth2 client at it. See `conformance/picus-security-conformance.yml`.
- The refresh token's **scope** limits which endpoints are reachable. A `403 FORBIDDEN` on an endpoint you expect to have usually means the token's scope (or the user's role) is too narrow — mint a token with wider scope rather than retrying.
- Store refresh tokens as secrets. They are long-lived and grant control of an offensive-security platform.

## Errors
- `401` — missing/expired access token, or the refresh token itself expired. Re-run step 1; if that fails, regenerate from the console. See `errors/picus-security-problem-types.yml`.
- `422` — malformed body on `/v1/auth/token`; the response is `{"errors": {...}, "message": "validation error"}`.
- `429` — rate limited; back off until `X-Ratelimit-Reset`. See `rate-limits/picus-security-rate-limits.yml`.
